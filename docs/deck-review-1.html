01 · THE PROBLEM

Every browser agent ships your page to the cloud

  • A job portal, an inbox, a checkout — the pages an agent works on are personal by definition.
  • Today's agents send a screenshot or a DOM dump to a remote model before any privacy decision is made.
  • The user cannot see what left, cannot take it back, and gets no proof of what was redacted.

02 · THE IDEA

Privacy as a pipeline, not a policy

  • Observe locally — DOM, accessibility tree, YOLO, OCR, faces, Florence-2, all on-device.
  • Redact locally — destructively, with placeholders. A fail-closed gate blocks dirty steps.
  • Plan in the cloud — open-weights models only, on the redacted observation.
  • Prove it — what was sent, egress audit, redaction proof, hash-chained audit log.

03 · ARCHITECTURE

Three parts, one rule

  • Extension (Chrome MV3): perception + guarded execution. Never writes the database.
  • Server (FastAPI, 127.0.0.1 only): planning, state, vault, proof. The only writer.
  • Planner: open-weights only (Gemma, Nemotron, Mistral, GPT-OSS) via our own gateway.
  • Page text is untrusted data at both planner and executor.

04 · THE PIPELINE

One step, nine stages

Observe → Detect → Redact → Gate → Second scan → Plan → Execute → Verify → Checkpoint + log.

  • Planner input capped at 8K tokens; history summarised at checkpoints.
  • Max 25 steps/task, 3 retries/step, 3 planner calls/step.
  • Never retry a submit, charge, or send.
