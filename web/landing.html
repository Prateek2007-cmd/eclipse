Eclipse

The browser agent that sees for you — and eclipses what no one else should see.

A privacy-first browser agent. It perceives the page on your device, redacts your personal data on your device, and only then asks the cloud what to do — with the redacted version only.

See how privacy works

How it works

1. Observe locally. The extension walks the DOM and accessibility tree, and runs YOLO, OCR, and face detection on-device. Florence-2 phrase grounding on WebGPU is built and is being verified on the demo laptop — it has not run in a real Chrome yet.

2. Redact locally. Names, emails, cards, faces are detected and blacked out or replaced with placeholders. A fail-closed gate blocks any step that still contains personal data.

3. Plan in the cloud. An open-weights model plans the next step from the redacted observation only. The executor verifies every action by re-observing the page.

Privacy in code

What the agent saw:

Name: Test User · Email: test.user@example.com · Card: 4111 1111 1111 1111

What the cloud got:

Name: [NAME_1] · Email: [EMAIL_1] · Card: [CARD_LAST4]

Card numbers, CVV, passwords, and OTPs never reach the planner, the logs, or the cloud. They are filled locally from an encrypted vault, after your approval.

FAQ

Does Eclipse send my data to the cloud?

Only the redacted observation. Raw personal data is redacted on-device before any cloud call, and a second scan runs before the planner sees anything.

Which models plan the actions?

Open-weights models only (Gemma, Nemotron, Mistral) through our own gateway. GPT-OSS was dropped as a planner after repeated empty responses. Proprietary models are never the runtime planner.

What happens when it hits a CAPTCHA?

It pauses, saves a checkpoint, and asks you. CAPTCHA, 3-D Secure, passkeys, and OTPs are human-only — no solver is built.

Can I check what it did?

Yes: what-was-sent, egress audit, redaction proof, and a hash-chained audit log you can verify. The hash chain proves tampering after the fact; it does not prevent it.
